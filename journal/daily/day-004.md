# Day 4 — Building the First Video Detection Pipeline

**Date:** October 19, 2026

## Objectives

- Prepare a video input directory for RoadFlow AI.
- Verify that OpenCV can open and inspect a video file.
- Build a reusable Python program for video object detection.
- Apply the pretrained YOLO11n model to individual video frames.
- Save an annotated output video for visual inspection.
- Record verified results, limitations, and the next development steps.

## Work Completed

### 1. Prepared the video input directory

Created `data/raw/` to organize input videos separately from source code.

Downloaded a small sample video and saved it as `data/raw/traffic.mp4`. This was the original sample used for the Day 4 experiment.

The input data directory is excluded from Git so that local videos are not accidentally committed to the repository.

### 2. Verified the video using OpenCV

Used `cv2.VideoCapture()` to open the video and inspect its properties.

Verified results:

- Video opened successfully.
- Resolution: 640 x 360 pixels.
- Frame rate: 30 FPS.
- Total frames: 62.
- Approximate duration: 2.07 seconds.

This confirmed that OpenCV could read the sample video before inference began.

### 3. Created the video detection program

Created `src/roadflow/detect_video.py`.

The program:

- Locates the project root and required input and model files.
- Opens the input video with OpenCV.
- Reads video frames sequentially.
- Loads the pretrained YOLO11n model from `yolo11n.pt`.
- Runs object detection on each frame.
- Uses a confidence threshold of 0.25 and CPU inference.
- Draws bounding boxes, class labels, and confidence scores using `result.plot()`.
- Writes annotated frames into a new MP4 video.
- Reports processing progress and the total number of detections.
- Releases the video reader and writer when processing finishes.

### 4. Ran the first video inference experiment

Executed the video detection program against the original sample video.

Verified results:

- Frames processed: 62.
- Detections accumulated across frames: 1,110.
- Output video was successfully generated.

The annotated video was saved to:

`runs/roadflow/video_detection/traffic_annotated.mp4`

The output was opened for visual inspection.

### 5. Reviewed the results

The annotated sample showed people detected by YOLO.

The program processed the video frame by frame and generated detection annotations. However, the sample contained a pedestrian scene rather than suitable road-traffic footage.

Therefore, this experiment verifies the basic video-processing pipeline but does not establish reliable vehicle-detection performance.

## Key Concepts Learned

### Video frames

A video is a sequence of images displayed over time. OpenCV reads these frames individually so that the detection model can process them.

### Object detection

YOLO predicts object classes, bounding boxes, and confidence scores for the current frame. The confidence threshold filters predictions; it does not represent overall model accuracy.

### Video annotation

The `result.plot()` method draws the detection results on each frame. OpenCV's video writer combines the annotated frames into a playable output video.

### Detection counts versus unique objects

The reported 1,110 detections are accumulated across frames. They do not represent 1,110 unique people or vehicles because the same object may be detected repeatedly in consecutive frames.

Object tracking will be needed to associate detections across frames and support reliable unique-object counting.

### CPU inference

The experiment ran on CPU because the verified PyTorch installation was CPU-only. Processing speed may be slower than on a compatible GPU.

## Limitations

- The sample video was not suitable for evaluating road-vehicle detection.
- No object tracking or persistent object IDs were implemented.
- No unique vehicle counting was implemented.
- No traffic-flow analytics or forecasting was implemented.
- No model training or fine-tuning was performed.
- Detection accuracy was not formally evaluated.
